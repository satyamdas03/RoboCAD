RoboCAD Twin

DRAFT FOR APPROVAL source: docs/designs/robocad-twin-deep-plan.md
THE ONE SENTENCE

The simulation model your hardware actually behaves like.

Kept true on every revision. Compile the CAD into a checked MuJoCo and URDF bundle, then identify the parameters that make sim match the bench, and report what changed when the hardware changes.

01

What changed and why

Plain CAD to sim export is crowded and mostly free. The paid problem sits one level up: keeping the sim true after the hardware, payload, or firmware changes.

WAS

RoboCAD Compile

CAD in, verified MJCF and URDF out. Useful, defensible only on check quality, and competing with free publishers and validators.

IS

RoboCAD Twin

Same compile layer, then calibration with honest intervals, gap metrics, and a revision regression report. The compile layer becomes the foundation, not the product.

Honest position today: zero customer interviews, zero letters of intent, no hardware partner. Every market statement in this plan is a hypothesis until interviews happen. The plan is built so the software does not silently depend on the unproven half.

02

What we are actually building

Two halves. Phase 1 is required and shippable on its own. Phase 2 is the reason anyone pays, and it needs one real robot.

PHASE 1 · M0 TO M7 · 6 TO 8 WEEKS

Compile layer

A STEP exported by hand from any CAD, Onshape included, comes in. Link grouping and joint inference with a human-editable YAML. Exact mass and inertia from B-rep geometry. Collision hulls. A verified bundle, a report with seven checks, a version diff, a living page, a CLI, and CI.

PHASE 2 · M8 TO M12 · 6 TO 8 WEEKS

Twin layer

A data contract a non-programmer can follow. Printed test protocols. Parameter identification with bootstrap and conformal intervals. Sim-to-real gap metrics per joint. Revision regression. Multi-simulator export. A page that overlays sim and real.

  • frozenAero, thermal, electronics, morphology, gait, brain, HERMES, marketplace, Isaac JSON. Behind a Labs flag, off by default. Tests stay green in the slow tier.
  • not in scopeNew physics solvers, new robot templates, new LLM features, cloud backend, accounts, billing.
  • hard constraintIdentified mass positive, inertia positive-definite with valid principal moments, friction non-negative. A model that violates this is never written.
  • hard constraintNo synthetic result is ever labelled real. No command is ever sent to real hardware. Protocols only, human supervised, with limits and a stop condition.

05

What done looks like

The end state in full. Each row is a claim that must be backed by an artifact someone else can open, not by a sentence in a README.

PHASE 1 DONE

STEP robots from any CAD compile to MJCF and URDF with a check report and a version diff.

Proof: three outside robots, three case studies, three living pages.

DISTRIBUTION DONE

CLI installable from PyPI, GitHub Action working on a sample repo.

Proof: clean-machine run under 15 minutes following the README.

CONTRACT DONE

A non-programmer records data that validates on upload.

Proof: one real run with a signed revision.yaml.

CALIBRATION DONE

Recovers known parameters on synthetic logs within stated tolerance.

Proof: twin_synthetic benchmark passing, labelled synthetic.

SIM-TO-REAL DONE

Held-out torque or trajectory error drops versus the uncalibrated CAD model.

Proof: improvement and its uncertainty reported on real logs.

REVISION DONE

Two real revisions produce a regression report a team would act on.

Proof: twin diff output naming the joint and the percent change.

TWIN PAGE DONE

Sim and real overlaid per joint, per revision, offline.

Proof: every number matches report.json and calibration.yaml.

08

Calls still open

These are not decided by the plan. Each one blocks a specific milestone.

  • decidedReview round 1 settled three scope questions: hand-exported STEP only, CLI first with the web flow deferred past M7, and MuJoCo as the only measured simulator claim. Recorded in the plan.
  • licenceApache-2.0 for the compiler core is the recommendation. Satyam decides. Blocks M0.
  • collision backendCoACD versus vhacdx. Neither is installed. Needs an install test on Python 3.14 before M3 commits.
  • outside robotsWhich three. Licences confirmed by Satyam before any derived model is published. Blocks M5.
  • fallback trackWhether usable public robot logs exist. One-day search scheduled week 5, before the week-8 decision.
  • onboarding demoWhether the generated biped stays as the demo, given it stands but does not walk. Blocks M6 framing.
  • partnerIdentity and robot. Nothing downstream of M8 can be called real until answered.
