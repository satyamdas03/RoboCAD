# RoboCAD 7.7 → 10.0 Roadmap Design

**Date:** 2026-09-16 (updated 2026-10-03)  
**Current baseline:** Phase 28A–F complete, Phase 29 complete, Phase 30 complete, Milestones A, B, C, D, E, **F**, and **G** complete, **407 default + 263 heavy/slow/mujoco tests passing** (1 xfailed, 2 xpassed), frontend build passes, honest complex-design confidence **9.6 / 10**.  
**Target:** **10 / 10** — fully automated, physics-validated, end-to-end design of complex robots.  
**Horizon:** ~12–24 months of focused, full-time engineering (6–12 months to ~9/10 was realistic; 12–24 months to true 10/10 including sim-to-real).  
**Execution model:** Full multi-month program split into 2–6 week ship-able milestones, each gated by tests and documentation. Milestones A–G are complete; Milestone H is next, gated on physical hardware access.

---

## 1. What 10/10 means

A user can describe a complex robot in one sentence, e.g.:

> *“Design a 1.2 m humanoid that can walk on a 5° slope, pick up a 2 kg box from the floor, and survive a 10 cm drop.”*

…and RoboCAD automatically produces:

1. A parametric `FeatureTree` that transpiles and executes without manual fixes.
2. A valid assembly with solved mates, self-collision-free across task poses, and manufacturing-aware geometry.
3. Actuators sized by inverse-dynamics / first-principles for the actual task.
4. A multi-physics verification pass: static/dynamic FEA on structural links, thermal/motor checks, drop test, vibration.
5. A morphology search evaluating 50+ candidates, each validated by real MuJoCo physics rollouts.
6. A MuJoCo / Isaac Sim / URDF bundle that loads first time, simulates stably, and exposes useful sensors/actuators.
7. A closed-loop brain policy trained on the actual robot model (not a 2-D abstraction) that reaches the task goal reliably.
8. A simulation certification report over randomized worlds; the design passes ≥ 95 %.
9. A single ranked result, certification badge, editable parametric code, manufacturing exports, and downloadable simulation package.
10. Deterministic, reproducible, auditable output every time.

**End-to-end time:** complex humanoid in **under 30 minutes**.

**Failure modes at 10/10:** essentially none for covered prompt classes. Out-of-scope concepts (soft robot, humanoid with wings) are rejected cleanly with an explanation rather than producing broken designs.

## 3. Roadmap phases and milestones

The program is split into **milestones**, each producing a shippable, tested increment. Dependencies are front-loaded so later milestones build on proven foundations.

### Milestone A — Gait robustness across morphology grid ✅ COMPLETE
**Target:** 7.7 → **8.0 / 10**  
**Duration:** 3–4 weeks (delivered)  
**Owner focus:** `ai_cad/gait.py`, `ai_cad/morphology_physics.py`, `ai_cad/morphology.py`, tests.

**Delivered:**
1. **Adaptive gait parameters.** `morphology_aware_walk_params` / `morphology_aware_balance_gains` scale gait period, step length, duty factor, hip/knee motion, and balance gains by COM height, leg length, robot mass, and foot geometry.
2. **Per-candidate gait sweep inside `physics_score_candidate`.** `_sweep_gait_for_candidate` tries 6 deterministic gait variants and keeps the best `walk_score`.
3. **Mass-aware actuator gains.** Position-actuator `kp`/`kv` now scale with total robot mass so light and heavy candidates both track well.
4. **Quadruped trot robustness.** Default quadruped walking switched from wave gait to dynamic trot; diagonal-pair offsets tuned.
5. **Regression tests.** `tests/test_gait_adaptation.py` and `tests/test_morphology_grid.py` assert humanoid grid ≥40%, quadruped grid ≥75%, and mass perturbations ≥50% `walk_ok`.

**Acceptance:**
- ✅ Full pytest suite green.
- ✅ Humanoid grid `walk_ok` rate 0% → ≥ 40%.
- ✅ Quadruped grid `walk_ok` rate 37.5% → ≥ 75%.
- ✅ Mass perturbation pass rate 0% → ≥ 50%.
- ✅ `README.md`, `PLAN.md`, `CurrentTo10.md`, dossiers, and memory files updated.
- ✅ Final verification: 380 default + 241 heavy/slow tests passing (1 xfailed).

### Milestone B — Structural dynamics / FEA for robot links ✅ COMPLETE
**Target:** 8.0 → **8.3 / 10**  
**Duration:** 4–6 weeks (delivered)  
**Owner focus:** `ai_cad/morphology_structural.py`, `ai_cad/solvers/`, `ai_cad/morphology.py`.

**Delivered:**
1. **Link cross-section extraction.** `ai_cad/morphology_structural.py` extracts length, cross-sectional area, and second moments of area for `limb_segment` / `link` parts.
2. **Lightweight beam checks.** Closed-form cantilever / simply-supported bending stress plus Euler buckling checks with self-weight, payload, and drop-impact factors.
3. **Deep FEA wiring.** Existing CalculiX dispatcher optionally verifies top-N candidates via `run_deep_structural_for_candidate`, degrading gracefully when CalculiX is absent.
4. **`structural_score` in morphology composite.** Failing links penalize the composite score (weight 0.05).
5. **Tests.** `tests/test_morphology_structural.py` covers extraction, stocky/slender beam cases, slender-humanoid penalty, deep-dispatch fallback, and morphology-search regression.

**Acceptance:**
- ✅ At least one humanoid morphology candidate with long thin limbs is correctly penalized.
- ✅ Deep solver dispatch passes for robot templates (or falls back gracefully).
- ✅ Full suite green.
- ✅ Final verification: 380 default + 246 heavy/slow tests passing (1 xfailed).

### Milestone C — Workspace, self-collision, and manipulability ✅ COMPLETE
**Target:** 8.3 → **8.5 / 10**  
**Duration:** 4–5 weeks (delivered)  
**Owner focus:** `ai_cad/morphology_workspace.py`, `ai_cad/morphology_collision.py`, `ai_cad/assembly_collision.py`, `ai_cad/morphology.py`.

**Delivered:**
1. **Sagittal-plane workspace proxy.** `workspace_proxy` replaces the broken 3-D volume metric with reach, X-Z sagittal reachable area, and lateral span.
2. **Self-collision checks.** `score_candidate_collision` samples neutral and flexed representative poses and runs pairwise assembly collision checks with articulated instance transforms.
3. **Manipulability index.** Topology-aware geometric Jacobian + Yoshikawa product-of-singular-values score for arm chains.
4. **Composite update.** `score_candidate` includes `collision_penalty` and `manipulability_score`; final weights: stability 0.22, workspace 0.20, gait 0.22, actuator 0.13, compactness 0.05, structural 0.05, collision 0.05, manipulability 0.08.

**Acceptance:**
- ✅ Humanoid arms no longer score `workspace_volume = 0.0 mm³`.
- ✅ Candidates with obvious arm-leg collisions receive lower composite scores.
- ✅ Full suite green.
- ✅ Final verification: 380 default + 250 heavy/slow tests passing (1 xfailed).

### Milestone D — Real end-effector families ✅ COMPLETE
**Target:** 8.5 → **8.7 / 10**  
**Duration:** 4–5 weeks (delivered)  
**Owner focus:** `ai_cad/part_families.py`, `ai_cad/morphology.py`, `ai_cad/robot_templates.py`, frontend morphology panel.

**Delivered:**

**Acceptance:**

### Milestone E — Topology grammar beyond templates ✅ COMPLETE
**Target:** 8.7 → **9.0 / 10**  
**Duration:** 8–10 weeks estimated; delivered in this session on top of the Milestone D scaffold.  
**Owner focus:** `ai_cad/topology_grammar.py`, `ai_cad/topology_composer.py`, `ai_cad/morphology.py`, `ai_cad/assembly_collision.py`, `web/backend/main.py`, `web/frontend/src/components/MorphologyPanel.jsx`.

**Delivered:**
1. **Topology grammar.** `ai_cad/topology_grammar.py` defines `Topology`, `LimbSpec`, `JointSpec`, `BaseType`/`LimbRole` literals; `default_topology` for `biped`, `quadruped`, `hexapod`, `wheeled`, `tracked`, `fixed`; `enumerate_topologies` with physical-feasibility pruning; `is_feasible`; stable `topology_hash`.
2. **Composer.** `ai_cad/topology_composer.py::topology_to_feature_tree` maps any feasible topology to a `FeatureTree` using `torso_plate`, `hip_hub`, `limb_segment`, and end-effector families; `_merge_family_default_parameters` injects family defaults into the tree-level parameter dict.
3. **Morphology integration.** `ai_cad/morphology.py` adds `TopologySpace`; `search_morphologies` enumerates, builds, and scores topologies with the existing physics/structural/collision/workspace/actuator/manipulability pipeline.
4. **Mesh caching.** `ai_cad/assembly_collision.py` caches meshes by family name so repeated family instances in topology trees share geometry.
5. **Backend.** `GET /morphology/topologies` and topology-aware `POST /morphology/search` with `topology_constraints`.
6. **Frontend.** `MorphologyPanel.jsx` adds Template/Topology mode toggle, base-type selector, appendage chips (`tail`, `arm`), and a topology column in results.

**Acceptance:**
- ✅ At least 5 distinct topologies can be generated and exported.
- ✅ Hexapod and wheeled topologies pass MuJoCo load and score non-zero.
- ✅ Default suite: **402 passing**; heavy/slow/mujoco suite: **261 passing** (1 xfailed unrelated attention-policy timeout).
- ✅ Frontend production build passes.
- ✅ `README.md`, `PLAN.md`, `CurrentTo10.md`, dossiers, and memory files updated.

### Milestone F — Real brain training on the actual MuJoCo model ✅ COMPLETE
**Target:** 9.0 → **9.3 / 10**  
**Duration:** 8–12 weeks (delivered)  
**Owner focus:** `ai_cad/geda_bridge/brain/envs.py`, `policies.py`, `trainer.py`, world builder.

**Delivered:**
1. **`WorldReplayEnv` implementation.** Replaced the stub with a real MuJoCo `gym.Env`-style wrapper around the generated world MJCF. Discovers actuators (with per-actuator `ctrlrange`), hinge/slide joints, freejoint torso, and task goal/object bodies; builds robot-specific observation vectors (joint positions/velocities, torso pose/velocity, task-error deltas); implements reward and termination for `walker`, `humanoid_stand`, `push`, and `pick_place` tasks.
2. **Policy training.** `RobotMLPPolicy` with adaptive `obs_dim`/`action_dim` and fixed hidden width produces a deterministic flat weight vector for CEM. `train_robot_policy` / `evaluate_robot_policy` / `train_and_evaluate_robot` train it with NumPy-only CEM and inner-rollout noise averaging.
3. **Reference trajectories + domain randomization.** World builder supplies deterministic domain randomization; training uses the exported MJCF directly.
4. **Replace brain smoke test.** `/morphology/{search_id}/candidates/{candidate_id}/simulate` exports the world MJCF, post-processes the robot with `_scale_masses_and_add_freejoint` for locomotion templates, builds a `WorldReplayEnv`, and runs real CEM training; gracefully falls back to `AbstractAttentionEnv` if MuJoCo is unavailable.

**Acceptance:**
- ✅ A trained policy produces measurable task success on a real generated humanoid or quadruped.
- ✅ Full suite green; heavy tests run real MuJoCo training.
- ✅ Final verification: **407 default + 263 heavy/slow/mujoco tests passing** (1 xfailed, 2 xpassed from the new real-robot brain tests); frontend production build passes.

### Milestone G — Automatic simulation certification ✅ COMPLETE
**Target:** 9.3 → **9.6 / 10**  
**Duration:** 4–6 weeks (delivered)  
**Owner focus:** `ai_cad/robot_certification.py`, `ai_cad/sim_certification.py`, `web/backend/main.py`, frontend.

**Delivered:**
1. **Robot-specific load cases.** `ai_cad/robot_certification.py` implements `RobotCertCase` enum and `run_robot_certification` that exports the robot to MJCF, post-processes masses/actuators/contacts, builds a procedural MuJoCo world with `uneven`/`stairs`/`slope`/`ramp`/`plane` terrain, applies deterministic domain randomization, and runs:
   - `terrain_walking` — morphology-aware gait on uneven ground.
   - `push_recovery` — lateral push with stronger force and longer recovery window.
   - `drop_test` — 5 cm drop followed by PD standing recovery.
   - `actuator_saturation` — walk test while tracking actuator force saturation ratios.
   - `payload_lift` — static torque-margin check for manipulation payloads.
2. **Automatic certification after design.** `ai_cad/sim_certification.py` detects robot designs and adds the `robot_randomized_world_certification` check (weight 0.25). Backend `MorphologySearchRequest.auto_cert` (default true) returns a certificate for the top candidate; `GenerateRequest.auto_cert` (default false) optionally certifies generated robot designs.
3. **Certification UI.** `CertificationPanel.jsx` surfaces pass/fail badge, readiness score, per-check list, and robot sub-case status. `MorphologyPanel.jsx` displays the top-candidate certificate after a morphology search.
4. **Pass threshold.** Each case uses a physics-grounded pass threshold; the aggregate certificate combines them into a readiness score.
5. **Post-ship walking demo.** `scripts/demo_morphology_walk.py` runs a fast heuristic morphology search, scores top candidates via the real `physics_score_candidate` path, and captures MuJoCo frames through a safe `step_callback` hook. The renderer callback does **not** call `mujoco.mj_forward()` after `mujoco.mj_step()` to avoid clobbering the solver warm-start.

**Acceptance:**
- ✅ A certified design survives the randomized-world distribution of tests.
- ✅ Full suite green.
- ✅ Final verification: **407 default + 263 heavy/slow/mujoco tests passing** (1 xfailed, 2 xpassed); frontend production build passes.

### Milestone H — Sim-to-real bridge (Phase 27D unblocked)
**Target:** 9.6 → **9.8 / 10**

2. **Calibrated domain randomization.** Match simulation parameters to measured real-world distributions.
3. **Safety-guarded deployment pipeline.** Detect out-of-distribution states and halt.
4. **Iterative sim-to-real tuning loop.** Real data → fine-tune policy → re-deploy.

**Acceptance:**
- One real robot skill works after sim-to-real iteration.

### Milestone I — Fully automated voice-to-certified-design pipeline
**Target:** 9.8 → **10 / 10**  
**Duration:** 3–6 months after Phase H  
**Owner focus:** HERMES orchestration, failure-recovery loop, audit trail.

**Deliverables:**
1. **HERMES orchestrates end-to-end.** Decomposition → topology selection → morphology search → physics validation → brain training → certification.
2. **Automatic failure recovery.** If certification fails, mutate parameters/topology and retry.
3. **Human approval gates.** Only for manufacturing spend or safety-critical changes.
4. **Complete audit trail.** From prompt to certified bundle.

**Acceptance:**
- User describes a complex robot; RoboCAD returns a certified, manufacturable, sim-ready design with no intermediate steps.

| **Test pyramid** | Unit → integration → simulation-load → end-to-end skill tests; tag heavy/slow/mujoco. |

| **Performance budgets** | Each physics-heavy candidate must complete in bounded time; cache MuJoCo models across candidates. |
| **Determinism** | All searches seedable; all tests reproducible. |

## 5. Risks and mitigations

| Risk | Mitigation |
|------|------------|
| Real gait is harder than expected | Start with trajectory-tracking + balance feedback; use per-candidate sweep; defer end-to-end learned walking to Milestone F. |
| MuJoCo rollouts are too slow | Cache models; parallelize candidates; use lightweight surrogate to pre-filter top-N. |
| Topology grammar explosion | Prune by physical feasibility rules; limit search depth/branch factor; require human constraints. |
| FEA dispatch unreliable | Keep lightweight beam formulas as fallback; real solver optional. |
| Brain training does not converge | Start with reference-trajectory tracking; use small MLP + CEM; domain randomize modestly. |
| Test suite becomes too slow | Tag physics rollouts as `mujoco`/`heavy`; run default suite in CI, full suite nightly. |
| Sim-to-real hardware unavailable | Keep Milestone H blocked; do not let it delay software milestones. |
