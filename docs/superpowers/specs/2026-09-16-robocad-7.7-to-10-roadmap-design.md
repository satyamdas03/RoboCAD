# RoboCAD 7.7 → 10.0 Roadmap Design

**Date:** 2026-09-16  
**Current baseline:** Phase 30 complete, 380 default + 232 heavy/slow tests passing, honest complex-design confidence **7.7 / 10**.  
**Target:** **10 / 10** — fully automated, physics-validated, end-to-end design of complex robots.  
**Horizon:** ~12–24 months of focused, full-time engineering (6–12 months to ~9/10, 12–24 months to true 10/10 including sim-to-real).  
**Execution model:** Full multi-month program split into 2–6 week ship-able milestones, each gated by tests and documentation.

---

## 1. What 10/10 means

A user can describe a complex robot in one sentence, e.g.:

> *“Design a 1.2 m humanoid that can walk on a 5° slope, pick up a 2 kg box from the floor, and survive a 10 cm drop.”*

…and RoboCAD automatically produces:

1. A parametric `FeatureTree` that transpiles and executes without manual fixes.
2. A valid assembly with solved mates, self-collision-free across task poses, and manufacturing-aware geometry.
3. Actuators sized by inverse-dynamics / first-principles for the actual task.
4. A multi-physics verification pass: static/dynamic FEA on structural links, thermal/motor checks, drop test, vibration.
5. A morphology search evaluating 50+ candidates, each validated by real MuJoCo physics rollouts.
6. A MuJoCo / Isaac Sim / URDF bundle that loads first time, simulates stably, and exposes useful sensors/actuators.
7. A closed-loop brain policy trained on the actual robot model (not a 2-D abstraction) that reaches the task goal reliably.
8. A simulation certification report over randomized worlds; the design passes ≥ 95 %.
9. A single ranked result, certification badge, editable parametric code, manufacturing exports, and downloadable simulation package.
10. Deterministic, reproducible, auditable output every time.

**End-to-end time:** complex humanoid in **under 30 minutes**.

**Failure modes at 10/10:** essentially none for covered prompt classes. Out-of-scope concepts (soft robot, humanoid with wings) are rejected cleanly with an explanation rather than producing broken designs.

## 3. Roadmap phases and milestones

The program is split into **milestones**, each producing a shippable, tested increment. Dependencies are front-loaded so later milestones build on proven foundations.

### Milestone A — Gait robustness across morphology grid
**Target:** 7.7 → **8.0 / 10**  
**Duration:** 3–4 weeks  
**Owner focus:** `ai_cad/gait.py`, `ai_cad/morphology_physics.py`, `ai_cad/morphology.py`, tests.

**Deliverables:**
1. **Adaptive gait parameters.** Replace fixed `default_walk_params`/`default_walk_balance_gains` with functions of:
   - `com_height_m`
   - total leg length `(thigh_length + shin_length)`
   - `robot_mass_kg`
   - foot contact geometry (foot_length, foot_width)
2. **Per-candidate gait sweep inside `physics_score_candidate`.** For each morphology candidate, run a small deterministic grid over:
   - `step_period_s`
   - `duty_factor`
   - `hip_swing_rad`
   - `knee_lift_rad`
   - `forward_bias_rad`
   - balance gains
   Select the configuration that maximizes `walk_distance_m` subject to stability constraints.
3. **Mass-aware actuator gains.** `_scale_masses_and_add_freejoint` currently sets `kp=600/kv=60` for all position actuators. Make `kp`/`kv` scale with body mass and inertia to avoid oscillation or sluggishness.
4. **Quadruped trot robustness.** Switch default quadruped walking from wave gait to trot; tune diagonal-pair offsets; target ≥ 75% of quadruped grid walking.
5. **Regression tests.** Add `tests/test_morphology_physics.py::test_humanoid_grid_walk_progress` and `test_humanoid_mass_perturbation_walk_ok`. Define concrete pass thresholds (e.g., ≥ 20/48 humanoid grid `walk_ok`, ≥ 24/32 quadruped grid `walk_ok`, ≥ 4/8 mass perturbations `walk_ok`).

**Acceptance:**
- Full pytest suite stays green.
- Humanoid grid `walk_ok` rate increases from 0% to ≥ 40%.
- Quadruped grid `walk_ok` rate increases from 37.5% to ≥ 75%.
- Mass perturbation pass rate increases from 0% to ≥ 50%.
- `README.md`, `PLAN.md`, `CurrentTo10.md`, and memory files updated.

---

### Milestone B — Structural dynamics / FEA for robot links
**Target:** 8.0 → **8.3 / 10**  
**Duration:** 4–6 weeks  
**Owner focus:** `ai_cad/verification_load_cases.py`, `ai_cad/solvers/`, `ai_cad/morphology.py`.

**Deliverables:**
1. **Link cross-section extraction.** For each `limb_segment` / `link` part in a morphology candidate, compute:
   - Outer bounding box or convex-hull cross-section
   - Second moment of area `I_min`, `I_max`
   - Effective length between joint centers
2. **Lightweight beam checks.** Add closed formulas:
   - Cantilever / simply-supported bending stress under self-weight + payload + drop load.
   - Euler buckling load for slender links.
   - Safety factor per link.
3. **Deep FEA wiring.** Use existing `ai_cad/solvers/verification_deep.py` to dispatch CalculiX for static stress / modal on the top-N morphology candidates.
4. **`structural_score` in morphology composite.** Penalize candidates whose links fail stress/buckling checks.
5. **Tests.** `tests/test_morphology_structural.py` with synthetic beam cases and real humanoid/quadruped candidates.

**Acceptance:**
- At least one humanoid morphology candidate with long thin limbs is correctly penalized.
- Deep solver dispatch passes for robot templates.
- Full suite green.

### Milestone C — Workspace, self-collision, and manipulability
**Target:** 8.3 → **8.5 / 10**  
**Duration:** 4–5 weeks  
**Owner focus:** `ai_cad/kinematic_tree.py`, `ai_cad/assembly_collision.py`, `ai_cad/morphology.py`.

**Deliverables:**
1. **Sagittal-plane workspace proxy.** Replace pure 3-D volume with a robust reachable-workspace score:
   - Max reach distance
   - X-Z sagittal reachable area
   - Y lateral span
   - Singularity-aware manipulability index sampled across the workspace
2. **Self-collision checks.** Sample task poses (walking, reaching, manipulation) and run pairwise `assembly_collision.py` checks per candidate.
3. **Manipulability index.** Compute Yoshikawa-style manipulability at representative arm poses; add `manipulability_score`.
4. **Composite update.** Add `collision_penalty` and `manipulability_score` to `score_candidate`.

**Acceptance:**
- Humanoid arms no longer score `workspace_volume = 0.0 mm³`.
- Candidates with obvious arm-leg collisions receive lower composite scores.
- Full suite green.

### Milestone D — Real end-effector families
**Target:** 8.5 → **8.7 / 10**  
**Duration:** 4–5 weeks  
**Owner focus:** `ai_cad/part_families.py`, `ai_cad/morphology.py`, composer/transpiler.

**Deliverables:**
1. **New part families.**
   - `parallel_jaw_gripper`
   - `three_finger_hand`
   - `vacuum_gripper`
   - `point_foot`
   - `compliant_foot`
2. **`_attach_end_effector` actually changes the tree.** Swap hand/foot family, update mass, CoM, and prompt string.
3. **End-effector scoring.** Include end-effector mass and workspace in the composite.
4. **Frontend selector.** Add end-effector picker to `MorphologyPanel.jsx`.

**Acceptance:**
- Morphology search with different end-effectors produces different feature trees.
- At least two end-effector families pass end-to-end export + MuJoCo load.
- Full suite green.

---

### Milestone E — Topology grammar beyond templates
**Target:** 8.7 → **9.0 / 10**  
**Duration:** 8–10 weeks (hardest layer)  
**Owner focus:** new `ai_cad/topology_grammar.py`, `ai_cad/decomposition.py`, `ai_cad/composer.py`.

**Deliverables:**
1. **Topology grammar.** A deterministic grammar for robot topologies:
   - Base type (biped, quadruped, hexapod, wheeled, tracked, fixed-base)
   - Limb count and attachment points on the base
   - Joint sequence per limb (revolute, prismatic, spherical)
   - Optional tail, arm, or head attachments
2. **Grammar search.** Enumerate grammar productions deterministically, prune by physical feasibility rules (e.g., walkers need ≥ 2 support contacts).
3. **Map productions to FeatureTree.** Generate `FeatureTree` assemblies from grammar productions using existing part families and composer.
4. **Run full physics pipeline.** For each topology, run standing/sway/step/walk/FEA/collision/manipulability scoring.
5. **Natural-language constraints.** Allow prompts to select or constrain grammar ("biped with arms", "quadruped with tail").

**Acceptance:**
- At least 5 distinct topologies can be generated and exported.
- Hexapod and wheeled-base templates exist and pass MuJoCo load.
- Full suite green.

---

### Milestone F — Real brain training on the actual MuJoCo model
**Target:** 9.0 → **9.3 / 10**  
**Duration:** 8–12 weeks  
**Owner focus:** `ai_cad/geda_bridge/brain/envs.py`, `policies.py`, `trainer.py`, world builder.

**Deliverables:**
1. **`WorldReplayEnv` implementation.** Replace the stub with a real MuJoCo `gym.Env`-style wrapper around the generated MJCF:
   - Observations: proprioception + selected sensors + task error
   - Actions: joint position/velocity targets or PD offsets
   - Reward functions per task template (walk, pick-place, push)
2. **Policy training.** Train small MLP / RNN policies with CEM / PPO / ES on the actual model.
3. **Reference trajectories + domain randomization.** Provide deterministic gait reference + randomized mass/friction/gains/sensor noise.
4. **Replace brain smoke test.** `/morphology/{id}/candidates/{id}/simulate` trains and evaluates on the real MJCF, not `AbstractAttentionEnv`.

**Acceptance:**
- A trained policy produces measurable task success on a real generated humanoid or quadruped.
- Full suite green; heavy tests run real MuJoCo training.

---

### Milestone G — Automatic simulation certification
**Target:** 9.3 → **9.6 / 10**  
**Duration:** 4–6 weeks  
**Owner focus:** `ai_cad/sim_certification.py`, `ai_cad/geda_bridge/world_builder.py`, frontend.

**Deliverables:**
1. **Robot-specific load cases.**
   - Randomized terrain walking (stairs, slope, uneven)
   - Payload-lift attempts
   - Lateral push recovery while walking
   - Drop test from specified height
   - Actuator saturation test
2. **Automatic certification after design.** Run certification automatically after `/generate` or `/morphology/search` for complex robot prompts.
3. **Certification UI.** Surface pass/fail, redesign suggestions, and certification badge in `VerificationPanel.jsx` / `MorphologyPanel.jsx`.
4. **Pass threshold.** Design must pass ≥ 95% of randomized worlds to receive a badge.

**Acceptance:**
- A certified design survives a distribution of tests.
- Full suite green.

---

### Milestone H — Sim-to-real bridge (Phase 27D unblocked)
**Target:** 9.6 → **9.8 / 10**  
**Duration:** 6–12 months, gated on hardware  
**Owner focus:** ROS 2 / micro-ROS bridge, telemetry logger, domain-randomization calibration.

**Deliverables:**
1. **System identification from real robot telemetry.** Fit actuator delays, friction, and sensor noise.
2. **Calibrated domain randomization.** Match simulation parameters to measured real-world distributions.
3. **Safety-guarded deployment pipeline.** Detect out-of-distribution states and halt.
4. **Iterative sim-to-real tuning loop.** Real data → fine-tune policy → re-deploy.

**Acceptance:**
- One real robot skill works after sim-to-real iteration.

---

### Milestone I — Fully automated voice-to-certified-design pipeline
**Target:** 9.8 → **10 / 10**  
**Duration:** 3–6 months after Phase H  
**Owner focus:** HERMES orchestration, failure-recovery loop, audit trail.

**Deliverables:**
1. **HERMES orchestrates end-to-end.** Decomposition → topology selection → morphology search → physics validation → brain training → certification.
2. **Automatic failure recovery.** If certification fails, mutate parameters/topology and retry.
3. **Human approval gates.** Only for manufacturing spend or safety-critical changes.
4. **Complete audit trail.** From prompt to certified bundle.

**Acceptance:**
- User describes a complex robot; RoboCAD returns a certified, manufacturable, sim-ready design with no intermediate steps.

## 4. Cross-cutting workstreams

These run across all milestones:

| Workstream | Responsibility |
|------------|----------------|
| **Benchmark discipline** | Run 30-prompt complexity suite after every model/generation change; publish scores. |
| **Test pyramid** | Unit → integration → simulation-load → end-to-end skill tests; tag heavy/slow/mujoco. |
| **Schema governance** | Version feature-tree, assembly, bundle, world-model, topology-grammar schemas; provide migrations. |
| **Documentation sync** | Keep `README.md`, `PLAN.md`, `CurrentTo10.md`, dossiers, and memory files in sync after each milestone. |
| **Git hygiene** | Commit per milestone: `robocad: Milestone A — adaptive humanoid gait grid`. |
| **Performance budgets** | Each physics-heavy candidate must complete in bounded time; cache MuJoCo models across candidates. |
| **Determinism** | All searches seedable; all tests reproducible. |

## 5. Risks and mitigations

| Risk | Mitigation |
|------|------------|
| Real gait is harder than expected | Start with trajectory-tracking + balance feedback; use per-candidate sweep; defer end-to-end learned walking to Milestone F. |
| MuJoCo rollouts are too slow | Cache models; parallelize candidates; use lightweight surrogate to pre-filter top-N. |
| Topology grammar explosion | Prune by physical feasibility rules; limit search depth/branch factor; require human constraints. |
| FEA dispatch unreliable | Keep lightweight beam formulas as fallback; real solver optional. |
| Brain training does not converge | Start with reference-trajectory tracking; use small MLP + CEM; domain randomize modestly. |
| Test suite becomes too slow | Tag physics rollouts as `mujoco`/`heavy`; run default suite in CI, full suite nightly. |
| Sim-to-real hardware unavailable | Keep Milestone H blocked; do not let it delay software milestones. |
